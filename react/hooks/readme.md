# React Hooks 学习

以use开头的函数，都是react hooks
- react api 最新的语法
- 函数 react 风格比较原生 JS， 更符合函数式编程的风格


## react 内置的
- useState 
   - 初始化传入一个**纯函数**或一个默认值 + 解包得到：
       - 一个状态变量 num
       - 一个更新 num 的函数 setNum
         调用 setNum 也可以传入一个函数，这个函数默认参数就是上一次state的值

       - 对比普通变量：
            函数内的普通变量在函数执行后就被销毁了，下次再执行的时候会就需要重新执行一遍
            但是num被Hooks机制“钩住”了（num变成状态state了），即使重新运行函数，num也不会重置，除非组件卸载了
    hook useState 为程序带来了关键的响应式机制
   - 状态（state）是变化的数据，也是组件的核心
> 纯函数：每次传入相同的输入始终返回相同的输出，且无副作用的函数（不修改外部状态，不依赖外部状态，不改变传入的状态）

   - 数据驱动视图/MVVM 模式：
       - 三个要素：
        1. State (状态/数据) ：应用的“心脏”，存储着当前的数据（如 num = 1 ）
        2. View (视图/UI) ：用户眼睛看到的界面（HTML/DOM）
        3. Event (事件/交互) ：用户对界面的操作（如点击按钮 onClick ）
      - **循环流程解析：**
        1. State -> View (数据驱动显示)
           - 箭头含义 ：状态决定长相。
           - 解释 ：React 根据当前的 State ，自动计算并渲染出 View 。
        2. View -> Event (视图产生交互)
           - 箭头含义 ：用户在界面上操作。
           - 解释 ：用户在 View （比如按钮）上触发了点击 Event 。
        3. Event -> State (事件改变数据)
           - 箭头含义 ：交互导致数据更新。  
           - 解释 ：事件处理函数（如 setNum ）被执行，修改了 State 。
         闭环（Re-render）：
            用户与页面交互 -> 事件触发了状态的改变 -> 状态改变驱动显示更新
        **一句话总结：**
            视图是状态的映射，交互是改变状态的手段（View = f(State)）

- useEffect
    effect 副作用
   - 对立面是 纯函数
     对于组件来说输入参数，输出jsx
     useEffect 异步请求数据，并且修改状态
   - 请求数据 副作用
   - 第二个参数 [] ? 依赖项

   - 三种使用情况：
      1. onMounted 挂载时一定执行，依赖项[]时，只执行一次
      2. 根据依赖项，[state, state2] 更新
      3. return 函数（闭包）在下一次执行effect前调用 或 组件卸载时调用
